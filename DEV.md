# 🔌 Firmware Development

## Technical Specifications

- **Board**: Arduino Micro / Pro Micro (ATmega32U4) or any AVR board with native USB HID.
- **Debounce**: Bounce2 library at 5ms.
- **HID**: Arduino Keyboard library v1.0.6.
- **Pin**: D7 with INPUT_PULLUP (pressed = LOW).
- **Default key**: 'l' (keycode 108), configurable via serial protocol or GUI app.
- **Pedal number**: 1-16 (default 1), configurable via serial protocol or GUI app.
- **Storage**: EEPROM, address 0 = keycode, address 1 = pedal number.

## Architecture Overview

The firmware uses `Bounce2::Button` to detect `pressed()`/`released()` transitions, calling `Keyboard.press()` and `Keyboard.release()` with the configured key code.

Keycode and pedal number are stored in EEPROM and can be configured via:
- Serial protocol commands (see [Serial Protocol](#serial-protocol) section).
- GUI configurator app.

### Hardware Wiring

- Connect a momentary foot switch between D7 and GND.
- Internal pull-up is enabled, so the circuit is: D7 — switch — GND.
- Pressing the switch pulls the pin LOW ("pressed").

### Runtime Behavior

- On press: logs (if DEBUG enabled) and calls `Keyboard.press(KEY_CODE)`.
- On release: logs (if DEBUG enabled) and calls `Keyboard.release(KEY_CODE)`.

## Pedal Number and USB Serial Number

All pedals are the same board with the same USB VID/PID, product and manufacturer strings, so the
operating system can't tell them apart. The pedal number fixes that without opening the serial
ports (which would disturb other serial devices like lightguns):

- The AVR core builds the USB serial number at runtime from the short names of all PluggableUSB
  modules. The Keyboard's HID module contributes `HIDxx`; the firmware's `PedalId` module (no
  interfaces, no endpoints) appends `PAAPnn` with the pedal number from EEPROM, e.g. `HIDPCPAAP03`.
- The configurator reads the serial number from the port list and shows the port as
  `PAAP Pedal 3 (COM5) [2341:8037]`. On Linux, each pedal also gets its own
  `/dev/serial/by-id/usb-…PAAP03-if00` link (with equal serial numbers, pedals share one link).
- After `PED<n>` changes the number, the firmware answers `ACK`, detaches from USB for 500ms
  (`UDCON.DETACH`) and attaches again, so the host reads the new serial number. The serial port
  disappears and comes back, possibly under a new name; the app waits for it and reconnects.
- Windows treats a new serial number as a new device and may assign a new COM port.

## Serial Protocol

The firmware speaks a line-based ASCII protocol at 115200 baud. Every command and response ends
with `\n` (responses with `\r\n`).

| Command | Description | Response | Example |
|---------|-------------|----------|---------|
| `HEL` | Connection handshake | `LO` | |
| `VER` | Request firmware version | `VER<version>` | `VER1.1.0` |
| `KEY` | Request current key | `KEY<key>` | `KEYl` |
| `KEY<key>` | Set key (printable ASCII) | `ACK` | `KEYa` → `ACK` |
| `PED` | Request pedal number | `PED<number>` | `PED3` |
| `PED<number>` | Set pedal number (1-16), then reconnect USB if it changed | `ACK`, or `ERR` if invalid | `PED4` → `ACK` |

Firmware 1.0 doesn't know `PED` and doesn't answer it; the app then disables the pedal number.
Unofficial builds report versions like `0.0.0+abc1234` (see [Release Process](#-release-process)).

### Testing Serial Protocol

Using Arduino Serial Monitor or any serial terminal at 115200 baud (newline line ending):
```
> HEL
< LO
> VER
< VER1.1.0
> KEY
< KEYl
> KEYk
< ACK
> PED
< PED1
> PED2
< ACK        (the pedal reconnects to USB now)
```

## Firmware Dependencies

The versions are pinned in CI (`.github/workflows/build.yml`); keep them in sync.

- Arduino AVR Boards core `arduino:avr` v1.8.6.
- `Keyboard` v1.0.6.
- `Bounce2` v2.71.0 (upstream: https://github.com/thomasfredericks/Bounce2).
- `EEPROM`, `PluggableUSB` (bundled with the AVR core).

## Prerequisites

### Arduino IDE
Install from [https://www.arduino.cc/en/software](https://www.arduino.cc/en/software), then
install the libraries via **Library Manager** (Bounce2 2.71.0, Keyboard 1.0.6).

### Arduino CLI (Alternative)
```bash
curl -fsSL https://raw.githubusercontent.com/arduino/arduino-cli/master/install.sh | sh
```

## Building Firmware

### Using Arduino IDE

1. Open `firmware/firmware.ino`
2. Select Board: **Tools → Board → Arduino AVR Boards → Arduino Micro**
3. Select Port: **Tools → Port → [Your Device Port]**
4. Verify/Compile: **Sketch → Verify/Compile** (Ctrl+R)
5. Upload: **Sketch → Upload** (Ctrl+U)

### Using Arduino CLI

```bash
arduino-cli core update-index
arduino-cli core install arduino:avr@1.8.6
arduino-cli lib update-index
arduino-cli lib install "Bounce2@2.71.0" "Keyboard@1.0.6"

# Compile firmware
arduino-cli compile --fqbn arduino:avr:micro firmware/

# Upload (replace with your device port)
arduino-cli upload --fqbn arduino:avr:micro -p /dev/ttyACM0 firmware/
```

### Finding Your Device Port

- **Linux:** `ls /dev/serial/by-id/` or `arduino-cli board list`
- **Windows:** Device Manager → Ports (COM & LPT)
- **macOS:** `ls /dev/cu.usbmodem*`

## Firmware Configuration

Edit [firmware/firmware.ino](firmware/firmware.ino):

- **Debug mode**: uncomment `#define DEBUG` to print events on Serial at 115200 baud.
- **Default key**: `DEFAULT_KEY_CODE` (see the [ASCII table](http://www.asciitable.com/)).
- **Pedal pin**: `PIN_PEDAL` (default D7).

### Customize USB VID/PID (Optional)

Not needed to tell pedals apart (that's what the pedal number is for); it only changes how the
pedal shows up in the operating system. Edit your board's `boards.txt` (Arduino install folder →
`hardware/arduino/avr/boards.txt`), then restart the Arduino IDE. For the Arduino Micro:
- `micro.build.vid=` to `0xF144` (OpenFire+1).
- `micro.build.pid=` to `0x1001` or `0x1002`.
- `micro.usb.usb_product=` to `PAAP_P1` or `PAAP_P2`.

## Troubleshooting Firmware

- **Port not found**: check the USB cable, try a different USB port.
- **Permission denied** (Linux): `sudo usermod -a -G dialout $USER`, then log out and back in.
- **Upload fails / bootloader not found**: press reset twice quickly to enter the bootloader, then
  upload within 8 seconds. Some USB hubs don't enumerate the bootloader; connect the pedal directly.
- **Keyboard not working**: the board needs native USB HID (ATmega32U4, SAMD, RP2040).
- **Key repeats unexpectedly**: increase the debounce interval (`pedal.interval(5)`).
- **Serial communication issues**: 115200 baud, `\n` line ending, no other program on the port.

# 💻 Configurator Development

## Technology Stack

- **Language**: Rust (edition 2024), toolchain pinned in `app/rust-toolchain.toml`.
- **GUI Framework**: [Slint](https://slint.dev) (winit backend, FemtoVG and software renderers).
- **Serial Communication**: [serialport-rs](https://github.com/serialport/serialport-rs).
- **Settings**: [confy](https://github.com/rust-cli/confy).
- **Logging**: `log` + `env_logger`.
- **Icons**: [Lucide](https://lucide.dev) (ISC License, see `app/ui/icons/LICENSE`).

## Prerequisites

Install Rust from [https://rustup.rs/](https://rustup.rs/). `app/rust-toolchain.toml` pins the
toolchain (with clippy and rustfmt); rustup installs it on the first `cargo` call in `app/`.

**Linux (Ubuntu/Debian):**
```bash
sudo apt install libudev-dev libfontconfig-dev pkg-config
```

**macOS / Windows:** no additional dependencies.

## Building and Running

```bash
cd app/
cargo run                 # debug build
cargo run --release       # optimized build
RUST_LOG=debug cargo run  # with protocol logging
cargo test                # unit tests
cargo clippy              # lint (CI fails on warnings)
cargo fmt                 # format (CI checks it)
```

Binaries end up in `app/target/{debug,release}/paap-configurator`. The release profile optimizes
for size (`opt-level = 'z'`, LTO, one codegen unit, stripped, `panic = 'abort'`).

## Code Architecture

- **`ui/app.slint`**: the whole user interface. It only renders the properties it gets and
  reports user actions through callbacks.
- **`src/ui.rs`**: `AppState` holds all state; `Controller::refresh` pushes it to the UI after
  every change. Serial I/O blocks, so connecting and saving run on a background thread (which
  owns the `Device` meanwhile) while the UI shows a busy overlay; a timer polls for the result.
  While disconnected, the device list refreshes every 2 seconds.
- **`src/serial.rs`**: `list_ports` sorts likely pedals first, `port_label` builds the device list
  entries (`… [VID:PID]`), `pedal_number` reads the pedal number from the USB serial number, and
  `Device` implements the protocol (connect handshake, save key, save pedal number).
- **`src/config.rs`**: theme preference, stored with confy.

### Saving a New Pedal Number

1. The app sends `KEY<key>` (if the key changed) and `PED<n>`.
2. The pedal answers `ACK` and reconnects to USB with the serial number `…PAAPnn`.
3. The app drops the old port, waits for a port whose serial number has pedal number `n` (up to
   10 seconds) and connects to it.

The app refuses pedal numbers that another connected pedal already uses, since it couldn't tell
the two apart afterwards.

## Debugging

- `RUST_LOG=debug cargo run` logs every connection step, including version, key and pedal number.
- Check the device responds to `HEL` with `LO` in a serial terminal.
- Make sure no other application has the port open.

# 🚢 Release Process

Releases are built and published by GitHub Actions following GitFlow; see [GITFLOW.md](GITFLOW.md)
and [.github/WORKFLOWS.md](.github/WORKFLOWS.md). App and firmware share one version and are
released together as `vX.Y.Z`.

1. Add your changes to the `[Unreleased]` section of [CHANGELOG.md](CHANGELOG.md).
2. GitHub Actions → **Release Start** → Run workflow (`kind: release`, choose the version part to bump).
3. Test the `X.Y.Z-rc.N` builds of the release PR on actual hardware.
4. Merge the release PR with **Create a merge commit**. This tags `vX.Y.Z`, publishes the GitHub
   Release and opens a back-merge PR into `develop`.

No version numbers are committed: `app/Cargo.toml` and `firmware/version.h` stay at `0.0.0`, CI
injects the version computed by `scripts/version.sh`. To build locally with a version:

```bash
scripts/version.sh                                                     # version of the checkout
(cd app && PAAP_VERSION=$(../scripts/version.sh) cargo build --release)
scripts/version.sh firmware-header "$(scripts/version.sh)" > firmware/version.h   # don't commit this
```

# 🤝 Contributing

## Code Style

### Firmware (C++)
- Follow Arduino coding conventions.
- Use descriptive variable and function names.
- Add Google-style documentation comments for functions.
- Keep functions focused and modular.

### Configurator (Rust)
- Follow standard Rust formatting: `cargo fmt` (CI runs `cargo fmt -- --check`).
- Check for common issues: `cargo clippy` (CI runs it with `-D warnings`).
- Keep the UI in `app.slint` free of logic; state and decisions belong in `ui.rs`.
- Keep serial communication in `serial.rs`.
- Add user-friendly error messages.
